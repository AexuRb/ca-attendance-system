# 大数据量与性能测试记录

## 1. 测试目的

本记录用于验证系统在协会多年累积数据规模下的查询、统计、导出、备份和前端渲染表现，并为后续优化提供可重复的基线。测试全程使用 `%TEMP%` 下的一次性应用目录和 SQLite 数据库，未读取或修改正式数据库。

测试日期为 2026-08-11。以下耗时只代表本次测试电脑上的相对结果，不作为所有电脑的绝对性能承诺。

## 2. 测试环境与规模

- Windows 10 专业版。
- AMD Ryzen 9 5900HX，31.4 GB 内存。
- Java 21.0.11 LTS，Python 3.14.3。
- 500 名成员。
- 10,000 条签到记录。
- 500 场培训、5,000 条培训参与记录。
- 1,000 条维修事务。
- 5,000 条操作日志。
- 数据日期跨越 2023-08-13 至 2026-08-11。

生成后数据库约 6.57 MiB，外键检查无错误。测试脚本会核对各表行数、执行 `ANALYZE` 和 WAL checkpoint，并在结束后删除一次性应用目录。

## 3. 常用接口基线

每个接口先预热 2 次，再连续测量 12 次。下表使用优化后的 P50 和 P95；P95 采用最近秩计算，在 12 个样本时接近最慢一次请求。

| 场景 | P50 | P95 | 平均响应体积 |
| --- | ---: | ---: | ---: |
| 成员分页 | 4.64 ms | 8.25 ms | 12.9 KiB |
| 签到记录分页 | 6.60 ms | 9.70 ms | 29.7 KiB |
| 待审核记录 | 11.46 ms | 13.24 ms | 143.7 KiB |
| 统计汇总 | 18.29 ms | 21.24 ms | 104.2 KiB |
| 周明细 | 4.78 ms | 5.31 ms | 14.7 KiB |
| 培训列表 | 5.34 ms | 24.82 ms | 48.8 KiB |
| 维修列表 | 4.32 ms | 26.60 ms | 56.3 KiB |
| 日志分页 | 2.79 ms | 4.08 ms | 15.1 KiB |
| 维护摘要 | 3.63 ms | 9.35 ms | 0.8 KiB |
| 自定义导出预览 | 66.44 ms | 82.17 ms | 1.9 KiB |

所有常用接口 P95 均低于 100 ms。培训和维修列表各出现一次 20 多毫秒波动，但中位数仍约 5 ms，未证明存在数据库查询瓶颈，因此没有为单次抖动追加索引。

## 4. 导出与备份

| 操作 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 全年统计 Excel | 3,057.26 ms | 1,692.88 ms | -44.6% |
| 自定义导出 Excel | 803.31 ms | 1,029.26 ms | +28.1% |
| 完整数据库备份 | 766.99 ms | 760.77 ms | -0.8% |

重型操作每轮只执行一次，后两项的差异应视为运行波动，而不是性能回归；相关代码在本轮没有变化。全年统计 Excel 是唯一稳定且可定位的瓶颈：原实现会对最多 366 个日期列逐列自动测宽，并在服务端计算全部公式。

优化后改用固定可读列宽，同时保留 Excel 打开时的公式重算标记。导出内容、合计公式和冻结窗格不变，耗时降低 44.6%。对应集成测试会检查列宽、合计公式和重算标记。

## 5. 浏览器渲染基线

在 1440 x 968 视口下，每个页面先预热 1 次，再完整加载 3 次。

| 页面 | P50 | P95 | 渲染项目 | 最大 DOM 节点 | 最大 JS 堆 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 成员 | 648.29 ms | 656.17 ms | 20 | 754 | 5.0 MiB |
| 签到记录 | 650.83 ms | 656.42 ms | 20 | 647 | 4.4 MiB |
| 培训 | 669.53 ms | 680.50 ms | 96 | 975 | 4.6 MiB |
| 维修 | 667.72 ms | 669.06 ms | 195 | 8,772 | 8.9 MiB |
| 日志 | 649.38 ms | 651.86 ms | 20 | 487 | 4.1 MiB |

当前页面均能在 700 ms 内完成完整加载，没有出现长时间冻结。维修页一次渲染 195 个项目和 8,772 个 DOM 节点，是最明确的增长风险；若单个自然年超过约 300 条维修事务，应优先增加服务端分页或分段加载，而不是继续扩大一次性列表。

2026-08-13 阶段性补充：上述维修页风险曾先通过服务端分页和三栏独立增量加载处理。每栏首次最多返回 30 条，标题总数来自数据库 `COUNT`；在 1,000 条测试数据下，看板单栏首页仍只返回 30 条，完整 Excel 保持 1,000 条。当时环境未提供浏览器自动化接口，因此没有用新的浏览器耗时覆盖历史基线。该阶段方案随后由下述最终状态工作区替代。

2026-08-13 最终验收进一步将培训和维修统一为服务端分页工作区，并补充真实浏览器自动化。隔离数据包含 200 场培训、5,053 条参与记录和 1,100 条维修；单场名单覆盖 0、1、30、72 和 3,000 人，维修状态精确为进行中 8、已完成 1,050、已取消 42。培训场次与页面名单每页显示 20 条，维修每页最多 30 条。

本轮 5 次接口样本中，培训分页 P95 为 4.96 ms，3,000 人名单分页 P95 为 5.87 ms，进行中维修分页 P95 为 4.19 ms，维修历史分页 P95 为 28.26 ms。3,000 人名单 Excel 导出约 0.66 秒，1,100 条维修完整导出约 0.86 秒。四档视口截图、导入导出、CRUD、协议预览和权限边界均通过，完整报告由 `scripts/run-performance-baseline.ps1` 生成到系统临时目录。

## 6. 查询计划与资源占用

- 成员、签到和日志使用分页接口。
- 签到日期查询使用 `idx_attendance_duty_date`。
- 培训参与人数子查询使用 `training_participants(session_id)` 唯一索引。
- 日志列表使用 `idx_operation_logs_created_at` 覆盖索引。
- 维修状态工作区执行分组 `COUNT + LIMIT/OFFSET`，页面不再一次读取和渲染全部当年记录；Excel 导出继续使用完整筛选结果。
- 完整测试结束后 Java 进程工作集约 558 MiB，私有内存约 620 MiB；该数字包含 Spring Boot、测试运行和 Apache POI 导出峰值。
- 构建后的前端 JavaScript 约 302.4 KiB，CSS 约 170.4 KiB；测试备份约 460.3 KiB。

## 7. 性能边界

本轮采用以下本机验收边界：

- 常用 API P95 不高于 200 ms。
- 常用后台页面完整加载 P95 不高于 1,000 ms。
- 全年统计 Excel、自定义导出和完整备份单次完成时间不高于 2,000 ms。
- 单页 DOM 节点不高于 2,500，JS 堆不高于 256 MiB。
- Java 进程工作集不高于 1.25 GiB，私有内存不高于 1.5 GiB。
- 页面操作期间不出现持续冻结或请求失败。

当前数据规模下均满足边界。性能工具会对这些绝对边界逐项检查；提供历史 JSON 时还会按 1.5 倍比例和各指标抖动余量比较，任一门禁失败均以非零退出码结束。维修页 DOM 增长已有分页保护，自定义导出预览也不再一次性加载完整结果。

## 8. 复测方法

先运行性能工具单元测试：

```powershell
Set-Location scripts
python -m unittest test_performance_baseline.py
```

再从仓库根目录运行完整基线：

```powershell
.\scripts\run-performance-baseline.ps1 `
  -OutputPath "$env:TEMP\ca-attendance-performance.json"
```

脚本会使用随机临时目录、随机临时凭据、18080/18081 测试端口，依次完成建库、造数、查询计划检查、API 测量、浏览器测量、功能与视觉验收、资源统计和性能门禁。默认结束后清理临时数据库和服务；仅排查问题时使用 `-KeepData`。可通过 `-BaselinePath` 指定一份历史报告执行自动回归比较。

生成的 JSON 应保存在 `%TEMP%` 或其他仓库外目录，不应提交到 Git。
