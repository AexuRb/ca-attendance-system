# 桌面端稳定性测试记录

## 1. 测试目标

本记录用于验证 Electron 桌面应用在 Windows 离线环境中的启动、单实例、托盘、后端进程、端口绑定、完整退出和整目录迁移行为。

最近复测日期为 2026-08-24。真实进程烟测使用 `%TEMP%` 下随机生成的应用根目录、Electron 用户目录和 SQLite 数据库，未读取或修改正式数据库。测试完成后会先结束本次启动的进程，再验证路径属于测试临时目录并清理数据。

## 2. 自动化覆盖

桌面端单元测试覆盖：

- 安装版、便携版、源码版和显式覆盖情况下的应用根目录解析。
- `data`、`backups`、`exports`、`logs` 持久化目录创建。
- 关闭窗口时隐藏到托盘，主动退出时允许窗口关闭。
- 隐藏或最小化窗口的恢复与聚焦。
- 记住密码的系统加密、迁移后无法解密时清理及加密服务不可用保护。
- 记住密码文件的同目录临时写入、原子替换和异常清理。
- `8080` 已有本系统、非 HTTP 程序占用 `8080` 和 `8081` 被占用的启动诊断。

- 桌面烟测环境变量只接受不短于 1 秒的明确场景。
- 窗口状态原子保存、损坏状态清理、离屏状态回收到可见显示器。

## 3. 本轮发现与修复

### 3.1 远程管理端口缺少启动前检查

原桌面端只在启动前探测 `8080`。如果 `8081` 已被占用，Spring Boot 会在启动过程中失败，用户只能得到较晚且不明确的后端停止提示。

现在启动前会同时检查两个端口，并区分：

- 本系统旧实例仍在运行。
- 其他程序占用 `8080`。
- 其他程序占用 `8081`，导致远程管理连接器无法启动。

### 3.2 源码模式可能使用系统 Java 启动器

测试发现当前电脑 PATH 中的 Oracle `javapath` 启动器会派生实际 JVM。Electron 记录的是启动器 PID，异常终止启动器后实际 JVM 可能继续监听端口。这不会影响发行包内固定 Temurin 的常规路径，但会降低源码运行和异常烟测的可靠性。

源码桌面端现在优先使用仓库 `runtime/temurin-21/bin/java.exe`，与发行包保持一致；仅在仓库运行时不存在时才回退到 `JAVA_HOME` 或系统 `java`。修复后异常停止烟测不再遗留 Java 进程或端口。

## 4. 离线与安全边界

- 桌面窗口只加载 `http://127.0.0.1:8080`，外部窗口打开和跨来源导航均被拒绝。
- 前端资源、后端 JAR 和 Java 运行时均为本地文件，真实进程烟测不依赖外部服务。
- `8080` 和 `8081` 实测只绑定回环地址，不直接暴露到局域网。
- `8081` 的远程角色与页面限制由任务 1 的权限测试覆盖。
- “记住密码”文件保存的是 Electron `safeStorage` 加密结果，Windows 上由当前用户的 DPAPI 边界提供机密性；文件采用原子替换避免断电或崩溃留下半写内容。`0o600` 在 Windows 上只是兼容性的尽力设置，安装目录中的数据子目录仍继承安装器 ACL，本机其他标准用户可能删除或替换该文件，但不能借此解密原凭据。
- 启动页使用仅允许本地资源和内联样式的 CSP；发行包内的第三方声明覆盖主要桌面、Java、后端和前端运行时组件。
- 安装包没有签名证书；本轮未构建安装包，因此没有重复检查 SmartScreen 展示，只复核了构建脚本继续关闭自动签名发现并生成 SHA-256 校验文件。

## 5. 复测方法

先确保 `backend/target/attendance-backend.jar` 已存在，并在 `desktop` 目录安装锁定依赖：

```powershell
Set-Location desktop
npm ci
npm test
Set-Location ..
```

再执行真实进程烟测：

```powershell
.\scripts\test-desktop-stability.ps1
```

脚本默认清理测试数据。排查失败时可以暂时保留隔离目录：

```powershell
.\scripts\test-desktop-stability.ps1 -KeepData
```

`-KeepData` 只应用于故障分析，检查完成后应删除脚本输出的明确临时目录。执行烟测前，正式桌面程序必须已经从托盘完全退出，确保 `8080/8081` 空闲。

## 6. 剩余人工检查

- 未签名安装包的 SmartScreen 文案只能在实际发布候选安装包上人工确认。
- 新电脑迁移仍应按《本地运行说明》进行一次实机抽查，确认目标电脑的文件权限和安全软件没有阻止运行。
- 不应在应用运行中直接复制 `attendance.db`；在线数据迁移应先完整退出，或使用后台备份功能。
