# 发布检查表

## 1. 版本与范围

- [ ] 明确发布版本、发布标题和用户可感知变化。
- [ ] `frontend/package.json`、`backend/pom.xml`、`desktop/package.json` 及两个 lockfile 版本一致。
- [ ] README、运行说明和下载文件名使用同一版本。
- [ ] `CHANGELOG.md` 已记录升级影响和数据库迁移说明。
- [ ] 当前提交包含计划内改动，没有混入 `tasks/` 或个人材料。

## 2. 数据与隐私

- [ ] Git 跟踪文件不包含 `data/`、`backups/`、`exports/`、`logs/`、`materials/`、`tasks/` 和 `release-artifacts/`。
- [ ] 未提交 `.db`、真实备份、Excel 导出、协议私密材料、记住密码文件或 `local-config.bat`。
- [ ] 扫描源码中没有访问令牌、真实密码、私钥或隧道凭据。
- [ ] 测试账号只出现在测试代码或隔离脚本中，不作为程序默认账号。

## 3. 常规 CI 自动门禁

- [ ] 后端 CI `mvn --batch-mode test` 通过，并完成 Maven 依赖上界检查。
- [ ] 前端 CI `npm test`、`npm run typecheck` 和 `npm run build` 通过。
- [ ] 前端构建后的 `backend/src/main/resources/static/` 与提交内容没有漂移。
- [ ] 桌面端 CI `npm test` 和所有 `.cjs` 语法检查通过。
- [ ] CI 脚本门禁通过：`python -m unittest discover -s scripts -p "test_*.py"`、Python 编译检查和 PowerShell 语法检查。
- [ ] 前端和桌面端生产依赖 `npm audit --omit=dev --audit-level=high` 没有高危或严重问题。
- [ ] CI 格式检查 `git diff --check` 通过。
- [ ] 测试数量只从 CI 运行时的 Surefire、Vitest、Node 和 unittest 报告读取，文档、提交说明和发布说明不手写固定数量。

常规 CI 不代替隔离业务冒烟、真实后端 UI 权限回归、性能基线或桌面真实进程验收；这些项目属于发布前手动门禁。

## 4. 发布前手动门禁

- [ ] 在仓库外的临时 `APP_ROOT` 中构建并运行 `scripts/run-isolated-smoke.ps1 -IncludeUi`；API 冒烟包含备份与恢复，临时数据、凭据、日志和截图均自动清理。
- [ ] 明确记录 `ui-core-workflows-test.py` 只是夹具驱动的前端渲染/工作流冒烟，不能作为后端权限证明。
- [ ] 执行 `scripts/run-role-ui-regression.ps1`，由隔离的真实后端和临时角色账号运行 `ui-role-regression.py`，核对页面入口、直接路由和接口权限；该脚本才是真实后端 UI 权限回归证据。
- [ ] 运行脚本性能测试和 `scripts/run-performance-baseline.ps1`，输出 JSON 放在仓库外，并按绝对阈值及可选历史基线检查；任务 12 的性能边界已完成复测。
- [ ] 生成用于手动验收的后端 JAR，并运行 `scripts/test-desktop-stability.ps1` 验证托盘、单实例、端口、异常退出和目录迁移。
- [ ] 在桌面、窄屏和浏览器缩放场景检查登录、签到、审核、导入、导出、备份恢复和权限边界。
- [ ] 完整 API 冒烟中个人资料更新返回 400 的已知失败已修复并复测；未修复前不能把完整 API 或发布验收标记为全通过。
- [ ] 发布说明明确安装包未代码签名，以及 SQLite 主库和备份未加密的已知风险。

## 5. 发行文件

- [ ] 安装版和便携 ZIP 均由 `scripts/build-desktop.ps1` 生成。
- [ ] 安装版文件名、便携版文件名和内部应用版本一致。
- [ ] 便携 ZIP 包含 `app`、`data`、`backups`、`exports`、`logs` 和启动说明。
- [ ] 安装包和便携版不包含真实数据库、凭据或个人材料。
- [ ] `SHA256SUMS.txt` 覆盖全部发行文件，重新计算结果一致。
- [ ] 安装包未签名的 Windows 安全提示已在 Release 说明中明确。

## 6. GitHub 发布

- [ ] 本地提交基于最新 `origin/main`，不存在未处理的远端提交。
- [ ] 提交已推送到 `main`，GitHub CI 全部通过。
- [ ] Release 标签与版本一致，并指向 `main` 上的发布提交。
- [ ] Release 上传安装版、便携版和 `SHA256SUMS.txt`。
- [ ] 从 GitHub Release 重新读取资产名称、大小和下载状态。

## 7. 回滚方案

1. 从上一版本 Release 获取安装版或便携版。
2. 从托盘完全退出当前程序。
3. 先复制并保留当前 `data` 与 `backups`，不要直接覆盖业务数据。
4. 仅替换 `app` 程序目录，重新启动并检查健康状态。
5. 如果数据库迁移后的数据不兼容旧版本，使用升级前自动备份恢复，不手工修改 SQLite。

发现权限绕过、数据不一致、无法启动、无法恢复备份或发行文件校验不一致时，应停止发布，不创建或撤回 Latest Release。
