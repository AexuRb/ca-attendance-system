# 发布检查表

## 1. 版本与范围

- [ ] 明确发布版本、发布标题和用户可感知变化。
- [ ] `frontend/package.json`、`backend/pom.xml`、`desktop/package.json` 及两个 lockfile 版本一致。
- [ ] README、运行说明和下载文件名使用同一版本。
- [ ] `CHANGELOG.md` 已记录升级影响和数据库迁移说明。
- [ ] 当前提交包含计划内改动，没有混入 `tasks/` 或个人材料。

## 2. 数据与隐私

- [ ] Git 跟踪文件不包含 `data/`、`backups/`、`exports/`、`logs/`、`materials/`、`tasks/` 和 `release-artifacts/`。
- [ ] 未提交 `.db`、真实备份、Excel 导出、协议私密材料、记住密码文件或 `local-config.bat`。
- [ ] 扫描源码中没有访问令牌、真实密码、私钥或隧道凭据。
- [ ] 测试账号只出现在测试代码或隔离脚本中，不作为程序默认账号。

## 3. 自动化门禁

- [ ] 前端测试、类型检查和生产构建通过。
- [ ] 后端完整测试和 Maven 打包通过。
- [ ] 桌面单元测试通过。
- [ ] Python 性能工具测试通过。
- [ ] 隔离业务冒烟通过，包含备份和恢复。
- [ ] 桌面真实进程稳定性烟测通过。
- [ ] `npm audit --omit=dev --audit-level=high` 无高危或严重生产依赖问题。
- [ ] `git diff --check` 通过。

## 4. 发行文件

- [ ] 安装版和便携 ZIP 均由 `scripts/build-desktop.ps1` 生成。
- [ ] 安装版文件名、便携版文件名和内部应用版本一致。
- [ ] 便携 ZIP 包含 `app`、`data`、`backups`、`exports`、`logs` 和启动说明。
- [ ] 安装包和便携版不包含真实数据库、凭据或个人材料。
- [ ] `SHA256SUMS.txt` 覆盖全部发行文件，重新计算结果一致。
- [ ] 安装包未签名的 Windows 安全提示已在 Release 说明中明确。

## 5. GitHub 发布

- [ ] 本地提交基于最新 `origin/main`，不存在未处理的远端提交。
- [ ] 提交已推送到 `main`，GitHub CI 全部通过。
- [ ] Release 标签与版本一致，并指向 `main` 上的发布提交。
- [ ] Release 上传安装版、便携版和 `SHA256SUMS.txt`。
- [ ] 从 GitHub Release 重新读取资产名称、大小和下载状态。

## 6. 回滚方案

1. 从上一版本 Release 获取安装版或便携版。
2. 从托盘完全退出当前程序。
3. 先复制并保留当前 `data` 与 `backups`，不要直接覆盖业务数据。
4. 仅替换 `app` 程序目录，重新启动并检查健康状态。
5. 如果数据库迁移后的数据不兼容旧版本，使用升级前自动备份恢复，不手工修改 SQLite。

发现权限绕过、数据不一致、无法启动、无法恢复备份或发行文件校验不一致时，应停止发布，不创建或撤回 Latest Release。
